# v1.46 — Invariant verification lifecycle

CYDRA v1.46 makes invariant verification a first-class persisted lifecycle.

## Lifecycle

`candidate → verification evidence → supported / contradicted / unresolved → hypothesis → observation → belief update`

### Guarantees

- Verification requires canonical evidence IDs; a boolean `verified=True` flag alone is not sufficient.
- Supporting and contradicting evidence remain separately attributable.
- Contradictory evidence prevents promotion to a supported invariant.
- Inconclusive evidence produces an explicit `unresolved` state.
- Only `supported` invariants can enter the verified-invariant hypothesis bridge.
- Verification transitions are recorded in graph history with evidence IDs, confidence, and rationale.
- New graph relationships are validated by the canonical semantic rules.

This preserves CYDRA's distinction between evidence, belief, and verified system properties.
