# v1.42 — Persistent Invariant Candidates

## Purpose

The reasoning orchestrator must not return invariant candidates only as transient Python objects. Candidate invariants are part of CYDRA's persistent system understanding and must be represented in the canonical `SystemModel`.

## Contract

- Candidates derived from evidence-backed relationships are persisted as `invariant` nodes.
- Candidate status remains explicitly `candidate`; persistence must not promote a candidate to a verified invariant.
- Source IDs, confidence, and evidence count are retained as attributes.
- Existing invariant nodes are updated rather than duplicated when the same candidate ID is encountered.
- Persistence never executes observations or changes hypothesis belief.
- Unauthorized observations remain excluded by the existing planner boundary.

## Architectural effect

v1.41 established orchestration and persisted the selected authorized observation plan. v1.42 closes the next persistence gap by retaining invariant candidates in that same canonical graph.
